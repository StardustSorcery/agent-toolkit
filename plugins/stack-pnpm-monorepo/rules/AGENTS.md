# pnpm Monorepo Architecture Guidelines

本ドキュメントは、pnpm workspace を利用したモノレポ構成において、エージェントが遵守すべきパッケージ境界、依存関係管理、およびビルド分離のアーキテクチャ原則を定めます。

---

## 1. ワークスペース構造とパッケージ分類

モノレポ内のパッケージは、明確な責務とレイヤに基づいて分離します。

```text
├── apps/                    # エンドポイント（Web, API サーバー, CLI 等）
├── packages/ (または libs/) # 共有パッケージ群
│   ├── shared-types/        # 型定義・インターフェース専用（実行時コード最小）
│   ├── ui/                  # 共通 UI コンポーネント（特定のバックエンドに非依存）
│   ├── domain/              # コアビジネスロジック・ドメインモデル
│   └── util/                # 汎用ヘルパー関数群（ドメイン知識非依存）
├── package.json             # ワークスペースルート
└── pnpm-workspace.yaml      # ワークスペース定義
```

---

## 2. 共有パッケージ境界と依存原則

1. **単方向依存の徹底 (Unidirectional Dependency)**:
   - 依存は「エンドポイント（`apps/*`） → 共有ライブラリ（`packages/*`）」の方向に限定します。
   - `packages/*` 同士の依存は、下位レイヤ（共通型やユーティリティ）に向かうもののみ許可します。
2. **循環参照の絶対禁止 (No Circular Dependencies)**:
   - パッケージ間の循環インポートは、ビルドエラーや実行時初期化不良（`undefined`参照）の原因となるため厳禁とします。
3. **責務の過剰集約の回避**:
   - 何でも入る「god package」を作らず、用途・変更頻度・依存対象に応じて小さく独立したパッケージに分割します。

---

## 3. 依存関係管理 (`workspace:*` プロトコル)

1. **内部パッケージ参照**:
   - ワークスペース内の他パッケージを参照する際は、バージョンを固定せず必ず `workspace:*`（または `workspace:^`）を使用します:
     ```json
     "dependencies": {
       "@scope/shared-types": "workspace:*"
     }
     ```
2. **外部依存の重複防止**:
   - 同一の外部ライブラリ（例: React, TypeScript, ESLint）を複数パッケージで使用する場合は、可能な限りバージョンを統一し、ルートまたは共有設定パッケージで管理します。
3. **peerDependencies の適切な宣言**:
   - React などのシングルトン性が求められるライブラリを共有 UI パッケージ等で利用する場合は、`peerDependencies` として宣言します。

---

## 4. ビルド・キャッシュ分離の原則

1. **独立したビルド成果物**:
   - 各パッケージは自律的に型検査（`tsc --noEmit`）およびビルド（`build`）が完了できる設定（`tsconfig.json`）を保持しなければなりません。
2. **暗黙的依存（Phantom Dependencies）の排除**:
   - `package.json` に明記されていないパッケージをソースコードから直接 import してはなりません。pnpm の厳格な node_modules 構造を活用し、依存漏れを検知します。
3. **成果物キャッシュの整合性**:
   - ビルドキャッシュツール（Turbo, Nx 等）を利用する場合、入力ファイル（ソース）と出力ファイル（`dist/` 等）の境界を明確に定義し、暗黙の副作用を排除します。
